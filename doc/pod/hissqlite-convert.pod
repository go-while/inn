=head1 NAME

hissqlite-convert - Convert an INN history database to the hissqlite method

=head1 SYNOPSIS

B<hissqlite-convert> [B<-m> I<srcmethod>] I<srcpath> I<dstpath>

=head1 DESCRIPTION

B<hissqlite-convert> performs a faithful, one-time migration of an existing
INN history database into a new hissqlite (SQLite) database.  It reads every
entry from the source history through the standard history interface and
bulk-loads it into a freshly created hissqlite database.

The conversion is keyed by hash: the history records only the MD5 of each
Message-ID, not the Message-ID itself, so the original Message-IDs cannot be
recovered.  Unlike a from-spool rebuild with B<makehistory>, this preserves
both the exact arrival, posting, and expiration timestamps and the
I<remembered> (token-less) entries, which a rebuild cannot reconstruct.

The new database is built in a temporary directory of its own, created in
the directory of I<dstpath> and named F<hisconv.>I<pid>F<.>I<n> (where I<pid>
is the process ID of B<hissqlite-convert> and I<n> a small number), and moved
into place only on full success, so an interrupted or failed run never leaves
a usable-but-incomplete destination.  B<hissqlite-convert> refuses to run if
the destination already exists, and never replaces a destination created
while it runs (for instance by another conversion, or by B<innd> started with
the new I<hismethod> too early), so two conversions to the same destination
cannot publish each other's unfinished database.  The database is published
with a hard link, so the file system of I<dstpath> must support hard links;
otherwise the conversion fails and its temporary directory is removed.

A failed run, or one stopped with SIGHUP, SIGINT or SIGTERM, removes its
temporary directory.  A run killed otherwise (for instance with SIGKILL, or
by a crash) leaves it behind: it is the F<hisconv.*> directory of the
directory of I<dstpath> whose name holds the process ID of that run, and it
can then be removed.

B<innd> must not be writing the source history while it is being converted.
After a successful conversion, set I<hismethod> to C<hissqlite> in F<inn.conf>
and restart INN; see hissqlite(5).  You may also want to audit the new
database with B<hissqlite-util> to ensure everything went fine.

=head1 OPTIONS

=over 4

=item B<-m> I<srcmethod>

The history method of the source database.  The default is C<hisv6>.

=back

=head1 ARGUMENTS

=over 4

=item I<srcpath>

The path to the source history.  For C<hisv6>, it is I<pathhistory>/F<history>
without any extension, as given by the I<pathhistory> parameter in
F<inn.conf>.

=item I<dstpath>

The path of the hissqlite database to create.  A F<.sqlite> suffix is
appended, so I<dstpath> should match I<pathhistory>/F<history> (the
resulting file is F<history.sqlite> in I<pathhistory>).

=back

=head1 EXAMPLES

Convert the default C<hisv6> history into a hissqlite database alongside it:

    hissqlite-convert /news/db/history /news/db/history

This creates F</news/db/history.sqlite>.
